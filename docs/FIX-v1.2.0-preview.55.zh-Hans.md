# preview.55：文件占用有限重试与延后预览文案（内部）

日期：2026-09-04。基线 preview.54 / `cae95cc`。按用户批准的小范围修复推进，不对外发布。

## 实际问题与边界

9 月 4 日 22:05 的批量保存中，MIKR-103 在提交文件时遇到占用，恢复时新 fanart 仍被占用，旧备份因此无法移回；批次停止在 28 成功 / 1 失败 / 42 未开始。后一次 71 部全部保存成功。只读检查确认该影片的恢复目录仍在，旧 fanart 备份与当前文件 SHA-256 相同；没有清理、恢复或改写真实媒体文件。日志不能确定占用进程，不归因于某一个外部程序或本软件预览。

## 修复设计

- `FileSharingRetry` 仅接受 Windows `ERROR_SHARING_VIOLATION` / `ERROR_LOCK_VIOLATION` 对应的 IOException HRESULT (`0x80070020` / `0x80070021`)。单次文件操作最多初始尝试加 3 次重试，异步延迟 100、200、400 ms；额外等待合计 0.7 秒，不代表整个事务/文件系统 I/O 有 0.7 秒完成时限。
- 单片、多分段的提交、备份、来源移除及回滚使用同一策略。成功移动后立即保留原有事务记账顺序；不重跑整部保存或重新下载图片，不提高并发，不改复制、校验、目标冲突判断。
- 权限不足、目标已存在、磁盘错误等立即交给原事务处理；`File.Move` 始终不强制覆盖目标。提交等待可以取消；恢复不继承已取消的任务 token，仍有限尝试恢复文件。持续占用时继续保留旧备份与恢复现场，不吞掉恢复错误、不自动清理。
- 新增日志只在共享冲突发生时记录操作、源/目标路径、重试次数与等待；正常保存不增加逐图片日志。
- 图片查看/下载逻辑不变。批量保存自动切片、未命中影片预览缓存且该角色有图片来源时，显示“预览未加载”，悬停解释批量保存期间暂不加载预览、图片仍依保存设置处理。四语言同步；已有缓存照常显示，无图片来源、已加载失败及缓存失败结果不冒充延后加载。

- 四语言 WPF 专项：延后状态不发 HTTP，文案/提示与排版、已有缓存复用、真实保存完成后的自动切片路径、真实缺图和下载失败、失败缓存、加载中及取消后的恢复。

完整门禁通过：Core **46/46**、文件事务回归 **40/40**、WPF UI smoke 及发布脚本验证 PASS，见 `artifacts/sharing55/final-gate.log`。新增四语言专项包含在默认 UI 门禁中，也通过 `--cover-checks` 单独运行；简体中文和日语合成截图已目视核对。
