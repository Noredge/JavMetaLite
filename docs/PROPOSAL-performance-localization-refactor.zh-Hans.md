# Proposal：流畅度、四语言与适度重构

日期：2026-09-04

审核记录：用户已于 2026-09-04 选择“平衡收尾”。下面保留提案时的静态审查与范围；实施结果另见 preview.47 收尾报告。

提案编写时：仅做静态代码审查和只读资源校验，尚未执行性能基准或修改应用/测试代码；对照版本为用户已试用的 preview.46。当前实施状态见 [preview.47 收尾报告](CLOSEOUT-v1.2.0-preview.47.zh-Hans.md)。

## 目标与原则

让 100 / 500 / 1,000 部影片的导入、浏览、选择与搜索反馈保持流畅，并降低以后维护四语言和界面行为的成本。性能提升必须由同机、同数据集的前后对照证明；不把代码行数减少等同于性能提升。

保留 WPF、Core/App 分工、每影片独立 MovieJob、字段/图片人工审核和文件事务保护。当前队列已经启用 Recycling 虚拟化及像素滚动，不重复建设这些能力。DMM 继续默认，R18 自选；不提高网站请求并发，不接入数据库或翻译功能。

## 静态审查发现

| 位置 | 已确认的代码行为 | 判断 |
| --- | --- | --- |
| MainWindow.SetBatchSelection / MovieJob.IsSelectedForBatch / MovieJob_PropertyChanged | 每个改变勾选状态的影片发出 IsSelectedForBatch、CanBatchSearch 两次通知，两者都会调用 RefreshQueueUi；后者刷新整个视图并多次遍历队列 | 全选/取消全选存在约 2N 次全队列刷新的路径，整体可能产生平方级工作量；耗时仍需测量 |
| MainWindow.AddMovieFilesAsync | 每部入队前线性查找已有分组，顺序载入本地资料后才激活第一部 | 大队列可检查分组索引、UI 更新批次和首个可操作时间 |
| MovieJobLoader / LocalArtworkDiscovery / ArtworkLocationHelper | 导入时逐部检查 poster、fanart 和所有本地样张；每张读取完整字节并调用尺寸解码，显示预览时还可能再次读取/解码 | 图片多的本地库是优先测量场景；不能通过取消损坏图片校验来换速度 |
| MainWindow._jobPreviews / LoadLocalSidecarPreviewAsync | 已访问影片的解码预览按 MovieJob 缓存，未见独立淘汰预算；主界面本地预览未设置解码尺寸。另一份在线字节缓存已有 12 项限制 | 并非没有缓存，而是缓存层级和预算不一致；内存可能随浏览过的影片数增长，不应直接称为内存泄漏 |
| LocalizationService / RefreshLocalizedPresentation | 切换当前语言资源字典，并手工刷新动态界面；刷新来源时内部调用 RefreshQueueUi，外层又调用一次 | 资源字典方案可以保留，需合并重复刷新和明确动态文本更新入口 |
| MoviePreviewState / CacheActivePreview / RestoreCachedPreview | 保存并恢复已经本地化的 FanartHint 字符串；语言切换及预览状态刷新没有重新格式化该尺寸提示 | 存在恢复旧语言文本的路径；实施前应补一条跨影片切换语言的 UI 复现测试 |
| MovieDiscoveryWindow.DiagnosticsText / Core diagnostics | 一些诊断和 exception.Message 直接进入界面，而 Core 部分消息固定为中文 | 常规界面已四语言化，但异常/诊断路径可能混入其他语言；系统错误原文可留详情，不必翻译日志 |
| MainWindow.xaml.cs | 当前 4,107 行，包含队列、搜索、图片下载/解码/缓存、来源菜单、偏好和保存调度 | 职责集中是维护风险，不单凭长度判断需要全面重写 |

### 四语言资源校验结果

- 简中、繁中、英文、日文各 480 个键；键集合一致，没有重复键或空值。
- 原始 XAML 文本每套约 45–52 KiB；没有证据支持“四套语言本身导致卡顿”的判断，运行时成本尚未测量。
- 三个旧 Browser 文案的占位符集合不一致。浏览器标题/说明的实际构造流程已经使用新的 Browser.Source* 键覆盖；因此先梳理旧 XAML 默认引用，不将它们直接当作已复现的用户界面故障。
- 现有 WPF 测试已覆盖语言键集合和主要控件布局；应补占位符契约、动态文本、缓存还原及异常场景，不重复已有检查。

## 建议工作包

### A. 性能基线（先做）

使用合成文件/获准测试副本，不触碰真实影片库。分别准备无 NFO、已有 NFO/封套、多样张、多 CD、重复路径和损坏文件场景；100 / 500 / 1,000 部规模。区分首次载入和重复载入，记录多次运行的中位数及较慢情况。

记录导入总耗时、第一部可用时间、UI 线程最长停顿、取消响应、全选/筛选/切换耗时、工作集和托管分配、图片读取/解码次数、每来源请求数及队列刷新次数。搜索先用固定延迟的模拟 HTTP 排除网站波动，不做真实网站压力测试。

交付：可重复运行的测试入口、基线数据和按收益/风险排序的瓶颈清单。测完再确定合理验收阈值，不承诺未经测量的倍数。

### B. 队列与导入优化（最高优先级）

- 批量勾选/取消时合并统计与视图刷新；普通单行变化只更新必要部分，不每次重建整个视图。
- 以分组键索引替代入队时的重复线性查找；保持已有多 CD 合并、顺序、去重和选中项规则。
- 将纯文件检查/解析工作与 UI 状态应用分离；分批提交到 UI，避免连续占用主线程。先不引入复杂的并行编辑。
- 区分“UI 消息循环被阻塞”和“当前操作按设计禁用控件”。第一轮改善响应和取消，不直接解除保存/搜索中的全局安全互斥；导入过程中能否审核部分结果是另一个需确认的交互变更。

验收重点：全选不再为每部影片重复刷新整队列；问题筛选、计数、焦点和取消结果与基线一致，100 部正常场景不倒退。

### C. 图片解码与缓存（最高优先级）

- 主界面采用适合显示尺寸的预览解码，仍保留原图真实分辨率和全质量输出；不能把缩略图误用于保存或来源分辨率比较。
- 测量并减少同一图片在“检查、读尺寸、预览”间的重复读取/解码；需要后台化的 CPU 工作不直接修改 WPF 控件。
- 为跨影片的解码预览建立明确预算和淘汰规则；与已有在线字节缓存、查看器加载任务协调，保留适当复用，不无限保留也不每次重下。
- 若测量发现同 URL 并发重复下载，再合并在途请求；失败/取消不能污染缓存或取消其他仍需要该图的使用者。
- 第一轮保留损坏图片检查及既有查看器预载语义。是否将全部本地样张检查改为延迟验证、是否调整预载优先级，在基线证明必要后单独确认。

验收重点：连续浏览很多影片后缓存占用有界；切换不串图，取消后不回填旧图；真实尺寸、图片来源和保存文件质量不变。

### D. 四语言维护与动态文本（高优先级）

- 保留 XAML 资源字典和 DynamicResource，不整体迁移 RESX/JSON，也不引入翻译框架。
- 合并语言切换期间的重复 UI 刷新。缓存保存尺寸、状态等原始数据，不保存已经翻译好的最终文案。
- 按实际用户可见路径补全诊断本地化：错误类型/标识和参数在 App 层格式化，技术详情保留原文；不把整个 Core 的日志都翻译一遍。
- 增加占位符参数一致性和格式化测试，扩展最小窗口/长文案、切换语言后返回另一影片、错误状态和对话框覆盖。审慎梳理旧键与默认引用。
- 可把资源整理为每键一行、按功能分组，方便 review；这是维护改进，不宣传为运行提速。
- 缺失键应有可诊断行为和合理回退；不先建设完整的自动代码生成或翻译管理平台。

验收重点：切语言及还原缓存不残留旧语言；四语言动态参数和异常提示一致；不改变影片标题、类型等用户 metadata 内容。

### E. 围绕上述工作的适度重构（次优先级）

按触及的职责逐步提取队列协调、图片加载/缓存、动态展示/格式化代码，让 MainWindow 主要连接界面事件与流程。名称和边界待实施时确定，不先设计通用框架。

保留现有 Core 中的搜索协调、审核会话和文件事务服务。优先给新边界建立测试，再搬迁实现；不把拆成 partial 文件视为已经完成职责重构。不为了重构改 UI 交互或一次迁移完整 MVVM。

验收重点：非 UI 行为可直接测试，减少对 MainWindow 私有字段反射的依赖；现有实际窗口冒烟测试仍保留，不以单元测试替代界面验证。

## 审核选项与建议

| 方案 | 范围 | 适用情况 |
| --- | --- | --- |
| 精简收尾 | A + 实测必要的 B/C + D 中明确的动态文案问题 | 希望尽快完成内部稳定版，尽量减少结构变化 |
| 平衡收尾（推荐） | A → B/C → D，按实际触及范围执行 E | 同时改善大队列体验和长期维护成本 |
| 全面架构重写 | 更换 UI/本地化框架、全面 MVVM 或重写全部服务 | 当前不建议；没有证据表明收益与风险相称 |

推荐选择平衡收尾，但分阶段交付：先基线，再队列/图片，再语言与必要职责整理；每一阶段可独立回归、审核和停止，不捆绑一个大改版。

## 完成门槛与范围外事项

- 同机同数据的前后对照，区分 CPU/UI、磁盘、图片及网站等待；没有收益的改动不因为“更优雅”而保留。
- 全量 Core/文件事务/WPF/便携包身份及哈希校验通过；保留 NFO 未知 XML、影片不覆盖、审核选择、冲突保护和取消恢复。
- 维持当前依赖与缓存，除非明确的实测问题需要调整；不盲目升级依赖、压缩代码、修改文件事务安全或提高 R18 请求压力。
- 不做 Jellyfin 插件、不接入本地全量数据库、不加新业务功能、不自动对外发布。
- 当前提案不会自动推进实现。由用户审核范围后再开始。
