## build48 实现与阶段验收（历史基线）

- 保持 `0.4.0` 预览版本号；build48 不代表正式 1.0，已发布 Preview 2 与 Windows Latest v1.2.3 均不变。
- 回滚按实际文件身份与内容核验所有已提交视频/侧车；先移入同卷隔离目录再检查，外部替换或改动会保留现场并要求恢复，不再删除外部文件。隔离与 NFO 临时文件使用固定长度随机名，合法长文件名不会因临时名扩展而溢出。
- WorkerClient 使用有界异步写队列，请求时限覆盖排队、管道写入与响应；部分帧中断会关闭传输并保留结果未知，不重放保存。
- 保存检查器新增事务恢复记录：核验文件、导出检查结果、明确确认后仅归档日志；归档重核验文件与存活会话，只让相关影片要求重新导入。丢失响应可核实状态，审核草稿保留并可导出数据型参考 JSON。
- 旧格式或证据不足的日志不会自动解除阻止；[手动核查流程](TESTING.md#legacy-transaction-records)要求保留原日志、核对文件和备份、退出全部实例后迁移，并重新导入预览。没有自动重放或盲目确认“已恢复”。
- 图片查看器本地解码失败显示错误与重试；重试重新取得预览，旧读者继续保有必要租约。
- 本机全量门禁通过：Portable 59/745 断言、Swift 97、Worker 103（协议 86、队列 4、保留状态 5、缓存 8），四语 512 键 / 4126 运行时检查。Windows 四项目交叉构建零错误、零警告；交叉构建不代表 Windows 运行时验收。
- 新增故障回归覆盖外部文件替换/修改、管道背压与部分帧、恢复核验/归档响应丢失、取消和草稿保留；真实 Worker 自动回归完成核验、归档、导出草稿、相关基线阻止、重新导入与再次保存。受控故障不代表断电或物理拔盘验收。
- 独立原生 QA 使用 `1a14b30` 候选 ZIP 的执行文件、单独 bundle ID/数据根及合成夹具，完成核验、取消归档、两份草稿 JSON 导出、确认归档、相关旧基线拒绝保存、无关影片取消/确认保存、移除重导和按参考手动补回草稿后再次保存。归档仅移动日志；最终仅两个明确保存的 NFO 改变，视频、图片、未知 XML/属性/注释/resume 保留。QA 已正常退出，用户原应用未被操作。
- Windows 首轮运行时门禁暴露提交前 ownership 读取未沿用共享占用重试，导致两个 late-lock 回归失败；修订将该读取纳入既有有限重试，不删除身份/内容核验，也不扩大为事务重试。原 late-lock 恢复断言保留，并增加占用释放后成功及提交 SHA 检查。后续同提交云端运行结果以 PR 门禁为准。
