# macOS architecture

SwiftUI/AppKit owns UI, per-job unsent drafts, file selection and Finder integration. The bundled console Worker owns the session, protocol, operation lifecycle, revision checks and immutable previews. Shared net10.0 Core owns providers, review, NFO round-trip and transaction execution. Windows stays WPF and injects its original image implementation.

Core's image boundary is IArtworkImageProcessor. The Windows implementation retains the existing static processor algorithm; the Worker uses pinned Skia. No WPF reference remains in Core. BatchSavePathConflicts moved into Core with a thin Windows adapter. Non-Windows actual video moves require verified full SHA-256 copying; no Unix root comparison establishes same-volume safety. The Worker exposes artwork generation/preservation, all three organization targets and stable sequential batch saves through those shared services. A copied video and its source are revalidated before retirement; a concurrent external edit retains recoverable copies.

All UI edits flush to MovieJob before search/preview. Worker accepts only server-issued planId, checks review revision and fingerprints, globally serializes saves, writes a recovery record, and invokes FileOrganizationService. It never writes final NFO directly. External modifications invalidate previews. The committed NFO is reloaded so another edit/save uses a fresh round-trip baseline. Every queued input remains protected even when not selected for saving. Imports and saves cannot overlap. The whole batch is preflighted before its first write; later item failure/cancellation preserves completed items and leaves remaining items unstarted. Confirmed multipart ordering is explicit and does not merge unrelated review state. When NFO output is disabled, refreshing the local baseline preserves the entire in-memory review.

The Swift WorkerClient launches an absolute in-bundle helper directly, asynchronously reads both pipes, matches response string IDs, and receives monotonic operation notifications. macOS 15 is the deployment floor. This build is local/ad-hoc, not a notarized distribution. A full Xcode project/shared scheme accompanies a SwiftPM Command Line Tools build path.

Process termination is distinct from a timeout or transport error. Only confirmed termination enables the recovery export/end-session flow; active native Trash and pending selection acknowledgements still block ending. The JSON export preserves last-received review snapshots and unsent drafts, labels operation outcomes unknown and carries no executable save plan. Export cancellation/failure never clears the session. No save is replayed, no old revision is reused and transaction journals remain the authority for disk recovery.

Worker-owned generated previews have byte/file/lease admission limits. Client-generated leases survive operation receipt eviction. The frontend retains at most 24 completed historical previews / 64 MiB, excluding visible readers and in-flight URL decoders. View disappearance releases reader ownership; invalidation keeps exact retired lease IDs until detached decoding actually returns. History eviction releases path/lease together while preserving reviewed dimensions/quality warnings. New admission waits for queued release acknowledgements; cancellation can revoke a reservation before generation finishes. Unleased contents are evicted under pressure. Ownership markers and an exclusive session lock allow startup to reclaim only recognized inactive directories, leaving active, legacy, foreign and unsafe directories untouched. Recovery is outside this cache lifecycle.

Series and ContentId retain the existing Windows/Jellyfin semantics. Series is an opaque preserved XML tag in baseline tests, not a newly invented output field; Mac therefore does not offer an ineffective edit control. Full metadata and actor structures still cross the protocol.

The browser has a narrow boundary: native WebKit captures bounded current-page data only on explicit import, while Core validates source and movie identity and preserves existing manual source-promotion rules. Web content has no native message handlers. A separate Trash lease spans Worker fingerprint/revision checks, actual NSWorkspace recycling and shared-job artwork refresh. It never delegates save execution to the browser or permanently deletes sidecars. NativeBridgeKit shares the production text/capture primitives with executable macOS tests; physical IME/VoiceOver acceptance remains distinct.

The primary Save action always obtains a Worker preview plan. A local preference may skip only its UI confirmation sheet; blocked/stale plans still require correction, and Worker revision, fingerprint, global conflict and journal checks are unchanged. Fresh queries promote configured provider values while retries retain reviewed choices; per-field source profiles are validated before any mutation.

Native Confirm Save is the consent to replace the NFO/artwork files listed in that immutable plan; there is no prerequisite overwrite checkbox. Native planning sends explicit sidecar replacement authorization, while Worker protocol defaults still reject unauthorized replacement from other callers. The opt-in skip-preview setting includes sidecar replacement and says so in its help text. It cannot overwrite videos or bypass cross-job collisions, revisions, fingerprints or transactions. Versioned native UserDefaults remember output controls, naming/destination/root, query source, recursive import and panel/disclosure visibility automatically; language, appearance and custom field sources retain their existing preferences. Worker startup supplies only the initial NFO-title fallback, never resets restored native controls. Queue entries, checked membership, drafts, plans, operation IDs and revisions are session state and are not persisted as preferences.

The embedded browser retains app-specific website state with WebKit’s default User-Agent. HTTP(S) top-level navigation/capture stays enforced; only child about:blank/srcdoc frames are additionally permitted for challenge widgets. Successful imports close the sheet only after the Worker acknowledges and refreshed review state is loaded. Live Cloudflare acceptance is independent of these configuration checks.

Sample checkbox acknowledgements are a separate serial review queue in the frontend. They keep optimistic checkbox values while leaving the workspace enabled; later operations wait for the queue before obtaining the current revision. Queue clear/removal cannot race this review queue, and close/quit waits for acknowledgements before checking unsaved state. A checkbox does not start or reset the global operation/progress state. Server-side artwork selection and all save protections remain unchanged.

First-use R18 manual navigation explicitly resolves its actual provider content ID without promoting metadata. Resolution runs as a cancellable read-only Worker operation, with source/session generation and review revision guards. Cached source URLs stay immediate. Failed resolution keeps site search available and does not enable import of the homepage.

The queue has one viewed movie and a separate checked set. Main queries, saves, retries and multipart review derive their scope from checks; zero checks disables query/save, without a viewed-row fallback. All/none changes only the checked set across the entire queue, including filtered rows. Batch overview is an explicit view of checked jobs and retains both artwork previews; navigation into one movie never changes checked membership. The worker-owned revision, preflight, plan and transaction layers are unchanged.

Preview preparation captures copied metadata/sidecar context under the workspace lock, then performs filesystem reads and plan/fingerprint creation outside it. Only a validated, current queue/revision may publish a plan; configuration revisions bind at publication. Cancellation ends the caller's wait and releases busy state without publishing a late result. One outstanding read-only preparation is bounded; while an OS read is still returning, a new preview fails closed with JOB_BUSY rather than accumulating readers. No save execution is replayed. On macOS, an existing original folder or selected custom root is validated by its exact Darwin metadata name without enumerating an unselected parent. File targets and new/moved directories retain the full alias check, and transaction/volume verification stays enforced.

Full snapshots parse each job once, reconcile native state against an ID index, and publish the ordered job array at most once; unchanged arrays are not republished. Authoritative snapshots still retire removed drafts/Undo sessions. Pipe framing scans only newly appended bytes and retains the 8 MiB limit and arbitrary fragmentation semantics.

Each native discovery confirmation or preview owns a local immutable sidecar directory inventory. Sibling movie/group eligibility and extrafanart ordering are shared within that operation; reused namespaces are rescanned before admission/publication. Filename/link/extra-directory changes fail closed. Single-use directories keep fresh standalone reads, and execution-time baseline, source/target fingerprints, whole-queue collision checks and transaction protection remain independent.
