# JavMetaLite 长期维护路线

更新：2026-09-05 · 稳定基线：1.2.0 · 原则：稳定优先、问题驱动，不为发版而改动。

## 近期重点

接下来两三周以日常使用为主，不要求重复整套验收，也不预设 1.3 开发日期。观察大队列导入与连续切片、长时间图片浏览、搜索取消／重试、批量保存与本地图片保护，以及四语言文案和布局。

遇到问题记录：版本、复现步骤、预期与实际结果、相关日志。公开前去除个人路径、真实媒体信息及凭据；优先用合成数据或获准副本复现。

## 问题优先级

| 类别 | 处理节奏 |
| --- | --- |
| 数据丢失、错误覆盖、恢复失败 | 立即优先排查，必要时提醒暂停相关操作；保留原文件与恢复现场 |
| 主要来源失效、保存失败、明显卡顿或常见交互错误 | 复现后做最小修复，补回归，按影响发布 1.2.x |
| 轻微排版、文案和新功能建议 | 先记录，积累真实需求后统一评估，不单独追求发版频率 |

## 每次补丁的固定流程

从当前 main 建维护分支 → 复现并补测试 → 最小修复 → 本地回归与用户必要回验 → 获准推送 → GitHub CI → 便携包复核 → 获准发布。

CI 保留 Core、文件事务、WPF、真实打包及独立 ZIP 校验。发布采用对应提交通过 CI 的同一份包，核对版本、许可、SHA-256 和启动；新增版本标签，不覆盖旧标签或旧 Release。原私人开发历史只留本地，不合回公开分支。

## 持续维护的边界

- 性能问题先看分段日志，再做同机、同数据、同缓存条件的对照；不牺牲文件安全换速度。
- 四语言继续使用现有资源字典；改文案时检查占位符、语言切换和默认／最小窗口布局。
- 依赖按安全或兼容性需要更新，不盲目追新；SDK、运行时和完整许可说明一起核对。保留可复用缓存，不自动清理恢复目录。
- R18 限流、可回退的候选 404、延后加载预览不直接视为产品故障；低分辨率提示不是模糊检测，队列仍只保存在内存中。

## 暂缓事项与重新评估条件

暂缓 R18 全量离线库、全面 MVVM／本地化框架迁移、跨影片并行提交和 Jellyfin 插件。只有反复出现的真实需求或可测量的瓶颈，才提出小范围方案，单独批准后实施。

无问题时不改代码；积累一批有效反馈后再复盘。不自动启用后台监控、定时任务或对外发布。
