# preview.54：极小竖图及本地封套漏检修复（内部）

日期：2026-09-04。基线为 preview.53 / `fb65bc6`。用户截图中 FNS-121 的完整封套位置实际是 147×200 的竖图，却没有黄色提示；按用户批准的补充方案修复，不对外发布。

## 原因与修复

1. 旧规则只判断横版图片，竖图全部绕过。新规则为：有效尺寸满足 `max(width, height) < 400`，或 `width > height && width < 600`，即标记低分辨率。最长边恰好 400 不属于“极小图”；原横版宽度规则独立保留。147×200、200×200 应提示，800×539、400×539 不提示。
2. 本地图片在导入时已经读取/解码验证，但尺寸没有带入队列的质量状态。现在 `LocalArtworkDiscovery` 保留验证所得的完整 fanart 尺寸，`MovieJobLoader` 在本地来源就绪后直接写入提示状态。不会重复读取图片，不启动在线搜索，也不必逐个点开影片。
3. 本地及在线完整封套预览将已经取得的原始尺寸同步给同一提示状态，不使用主面板缩放后的尺寸。已知结果取消相同影片的冗余待检查任务；修订号阻止旧来源的预览/后台结果覆盖当前选择。重新读取本地同路径的新图片会更新判定；读失败为未知，不继续显示旧低清判定。

只检查完整封套/fanart 位置；缺少 fanart 时不拿裁剪 poster 或样品图代替。队列依然只显示黄色“待审核”，原因与尺寸在主面板显示；本地影片仍可搜索，质量状态不修改审核修订号，不阻止保存、不修改已有媒体/NFO、不自动切换来源。保留原来的失败/缺少番号提示优先级。

## 验证

新增/扩展专项测试：

- 147×200、200×147、200×200、399×399、最长边 399/400、宽度 599/600、0 尺寸、普通竖图与横图边界。
- 六部合成本地影片：极小竖图、正常横版、极小方图、正常竖图、仅有 poster、损坏 fanart；未打开的影片也已正确分类。
- 导入使用与旁车校验结果相同的尺寸对象；本地载入、预览、切片全过程 HTTP 请求数为零。
- 锁住已缓存的 fanart 文件后切回影片，仍正确显示缓存预览和黄色状态；强制新预览读取同路径替换图片后能清除/恢复提示，损坏的新图片不会保留旧低清判定。
- 本地低清条目在四语言下均为黄色“待审核”，不在队列列出尺寸，纳入问题筛选，保持可搜索和可保存。
- 新预览结果到达后停止冗余后台检查；刻意忽略取消的旧后台回复也不能覆盖最新预览。影片/NFO 文件哈希保持不变。

全部采用合成文件、纯色图片及禁止联网的测试 handler；不使用用户真实影片库，不压测在线网站。专项入口沿用 `--cover-checks`；材料保留在 `artifacts/cover54/`。

最终完整门禁通过：Core **46/46**、保存/文件事务回归 **36/36**、WPF UI smoke 和发布脚本验证 PASS，见 `artifacts/cover54/final-gate.log`。既有两处 1×1 本地/手动封套测试的尺寸提示断言更新为低清提醒，保留其来源、保存可用性及本地 NFO 安全性等原断言。专项复跑通过，合成界面截图 `artifacts/cover54/final-ui/tiny-local/tiny-local-warning.png` 已目视核对。
