# preview.53：批量低分辨率封套提示（内部）

日期：2026-09-04。基线为 preview.52 / `e4d607c`。按用户批准的轻量方案实现；不对外发布，不调整既有 404 图片回退处理。

## 用户可见行为

- 单片或批量自动搜索成功后（包括部分来源成功），只检查最终选中的完整封套。批量搜索先完成资料读取，再后台补检，不等待全部尺寸检测才恢复编辑。
- 成功读取的横版完整封套满足 `Width > Height && Width < 600` 时，队列现有“待审核”标签变为黄色，不增加原因或尺寸文字，纳入既有“有问题”筛选与统计；点开影片后主面板尺寸提示显示具体警告和实际尺寸。600 像素边界不标记，800×539 不标记。已有来源失败等独立状态保留。
- 只提醒，不影响保存资格、搜索状态、样品图选择或审核版本。不会自动切换至 R18，不下载其它来源或全部样品图来评分。
- 换来源、修改番号、重新搜索时清除旧测量；晚到的旧来源结果、已移除或已销毁影片的结果不能覆盖当前状态。停止检查保留已经完成的测量，后续重新搜索或换来源可再次检查。
- 底栏检查进行时提供“停止封套检查 (剩余数)”，无需确认。运行前台任务时恢复原有“取消当前操作”；新检查暂停启动，已启动的最多两项可结束。取消前台任务也停止待检查任务，关闭程序/移除影片会取消相应读取。
- 四语言提示保持统一，不新增偏好设置、配置迁移、依赖或持久化数据库。只导入本地队列不会自动发起在线检查；已搜索影片切回本地来源时，只读本地完整 fanart，不用裁剪 poster 代替。

## 实现与性能边界

- `CoverResolutionCheck`：仅存成功位置和原始尺寸，使用既有候选顺序逐个回退。失败、缺图或尺寸未知不是低分辨率判定；竖图和方图暂不按横版封套阈值判断。
- `MovieJob`：独立的尺寸检查修订号及只读提示状态。更新检查结果不会调用 `TouchReview`，因此不会让已经确认的保存预览过期。
- `CoverResolutionMonitor`：Dispatcher 管理轻量待办条目，最多两项运行；网络读取与图片解码放在线程池，不给所有影片提前创建任务，不保留整队列位图。
- 复用主面板已有尺寸测量；远程地址尺寸缓存上限 256 项，原始图片仍使用既有最多 12 项的预览缓存，本地文件重新读取实际尺寸。未知地址仍需图片请求/解码；缓存不覆盖整队列，不能承诺完全避免重复请求或没有额外带宽成本。
- 检测的是像素尺寸，不是清晰度评分。大尺寸但模糊/人工放大的图片可能不会被标记；初始 600 像素阈值等待用户真实低清样本校准。
- 保存服务、文件事务、DMM/R18 搜索并发及限流策略均未改动。不会因为低清提示自动替换或删除用户图片。
