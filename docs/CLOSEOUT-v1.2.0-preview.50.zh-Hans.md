# preview.50：连续使用稳定性收尾（内部）

日期：2026-09-04。基线：preview.49，本地提交 `3bb0422`。用户已认可载入/切换预览的流畅度，本轮按既定下一阶段补充连续使用验证，只修复实际复现的问题。

## 复现与修复

在真实 WPF 队列选择事件中模拟一个尚未返回的图片请求：

1. 选中影片 A，图片加载中点击“取消当前操作”。
2. 切换到影片 B，其预览正常显示。
3. 切回 A。

preview.49 会在离开 A 时把尚未完成的空白预览存入缓存；返回 A 时命中这个缓存，不再请求图片。旧版本测试实际报错：`Canceled preview was cached as complete; revisit must reload. slowCalls=1, image=False.`

修复限定在主窗口预览生命周期：

- 只有完整执行结束或从有效缓存恢复的预览，才允许再次存入缓存。
- 开始重新载入/切换图片来源时，使旧缓存失效；取消或中断不能把空白/不完整的结果标为完成。
- 取消时刷新图片状态提示，不继续显示“加载中”。
- 正常完成但确实缺少图片的结果仍可缓存；已完成预览继续复用，不把所有空白状态当成错误。

回归覆盖初次加载取消，以及已经缓存过图片后取消新来源加载；再次进入分别重新载入正确图片和来源。未改动队列刷新策略、来源路由、网站并发、UI 布局、四语言资源、依赖或任何保存保护。

## 连续测试结果

先跑 40 部 × 2 轮短测，再用 **同一个主窗口**运行 1,000 部 × 5 轮，不通过每轮重启清除潜在累积。每轮包括：

- 导入包含 NFO、poster、fanart、4 张样品图的合成影片，再重复导入确认去重。
- 通过队列选中操作连续查看 36 部，检查原图尺寸提示与有界缓存。
- 打开一次完整图片查看器，验证没有错误复用缩小后的主界面预览。
- 切换四种语言；取消一次模拟 DMM 批量搜索。
- 完整搜索，模拟 10% HTTP 500，再仅重试失败来源；最后清空队列。
- 清空后推动 Dispatcher，再在计时之外执行 GC，用弱引用检查所有已移除 MovieJob 是否可回收，并记录资源状态。

没有发现本测试范围内旧影片对象持续驻留。托管内存仍从约 5.75 MB 增至 5.99 MB，不能宣称“零增长”或完全排除长时间原生资源泄漏。每轮总耗时 39.18–44.74 秒，本轮不以时间阈值判定通过，也不把这一连续测试当作前后性能对照。

在线图片的针对性延迟测试另行验证：先切换到新图片，再让旧请求返回，新图片不会被覆盖；关闭查看器会取消未完成加载。连续千片测试使用本地合成图片和无在线图片的模拟搜索结果，不代表已经验证长时间大量在线图片下载的内存行为。
